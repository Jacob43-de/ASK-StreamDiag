Abstract 1
Standard streaming LLM evaluation only outputs binary pass/fail feedback, which cannot 2
pinpoint which intermediate reasoning step causes model failure, nor distinguish failures3
caused by permanent capability gaps versus prompt activation instability. To resolve this 4
limitation, we introduce ASK-StreamDiag, a fine-grained streaming evaluation framework 5
built on atomic subtask decomposition and standardized prompt perturbation-based knowl- 6
edge boundary classification. Our pipeline first splits complex code, medical diagnosis 7
and tool-use tasks into domain-specific atomic subtasks, then employs a strong judge LLM 8
to generate structured per-subtask failure records. We further categorize each failed sub- 9
task into MSU-like (unrecoverable across prompt variants) or PSK-like (prompt-sensitive)10
failure types via a fixed set of 3-4 prompt perturbation templates. We validate our frame- 11
work on three public benchmarks (DS-1000, DDXPlus, ToolBench) with human-annotated 12
gold failure labels to calibrate diagnostic accuracy. Controlled budget-matched baseline 13
experiments confirm that the fine-grained subtask diagnosis module, rather than stronger 14
external LLM models, drives improved post-failure recovery performance. Ablation, hy- 15
perparameter sensitivity and cross-domain generalization analyses verify the robustness of 16
our subtask decomposition and MSU/PSK classification modules. Finally, we demonstrate 17
that MSU/PSK-aware adaptive prompt rewriting and model routing achieve a balanced 18
tradeoff between inference cost and task completion rate under streaming deployment 19
scenarios. We release annotated fine-grained failure diagnostic samples to support future 20
LLM evaluation research. 21

1. Introduction 24
Paradigms for large language model (LLM) evaluation are undergoing a critical transi- 25
tion, shifting from benchmarking what LLMs are empirically capable of accomplishing to26
dissecting the root causes underlying their success and failure modes. While conventional 27
static benchmarks quantify the inherent competence of LLMs effectively, they only deliver 28
binary right/wrong annotations and fail to unpack the intrinsic drivers responsible for erro- 29
neous model outputs [ 1,2]. In parallel, dynamic streaming evaluation pipelines exemplified 30
by StreamBench enable continuous performance tracking with iterative user feedback, yet 31
they are plagued by coarse evaluation granularity. Under such coarse-grained protocols, 32

A tangible case derived from the DS-1000 Python code generation benchmark fur- 42
ther elaborates this methodological defect [ 5]. Consider a query requesting a dynamic 43
programming-based function for Fibonacci sequence computation; the corresponding 44
model-generated code fails unit testing protocols. Traditional evaluation workflows can 45
only flag this instance as a generic failed case. Nevertheless, this single binary label masks 46
a broad spectrum of underlying fault origins: the model may misinterpret core algorithmic 47
constraints (e.g., adopting recursive implementation instead of dynamic programming 48
paradigms); logical flaws may emerge in control flow design such as inappropriate loop 49
boundaries or invalid recursive base cases; variable assignment and data structure ma- 50
nipulation may contain operational mistakes; or the generated code may simply violate 51
Python syntactic specifications. Legacy evaluation protocols cannot differentiate these 52
distinct failure sources, treating LLMs as opaque black-box systems that exclusively output 53
dichotomous pass/fail signals. A more counterintuitive observation lies in inconsistent 54
cross-instance performance: an LLM may solve one highly analogous query flawlessly 55
while collapsing entirely on a near-identical counterpart. Such volatile behavior rarely 56
points to critical knowledge deficits but instead reflects prompt susceptibility—relevant 57
knowledge is internally encoded within model parameters yet cannot be properly acti- 58
vated by specific prompt formulations. As Yin et al. argued, assessments relying on fixed 59
question sets or limited rephrasing variants lack robustness and comprehensiveness, given 60
LLMs’ extreme sensitivity toward prompt lexical and structural design [ 6]. To resolve 61
this drawback, the authors formalized the knowledge boundary construct to differentiate 62
prompt-agnostic knowledge and prompt-dependent susceptible knowledge [6].63
Deficiencies embedded within conventional evaluation paradigms have become in- 64
creasingly conspicuous in recent literature. Static benchmarks represented by MMLU 65
have long served as the de facto gold standard for LLM quantitative assessment, yet 66
contemporary empirical evidence indicates that state-of-the-art LLMs attain over 90% ac- 67
curacy on these testbeds, indicating prominent performance saturation effects [ 1]. More 68
critically, Gema et al. performed a thorough error auditing on MMLU and uncovered 69
pervasive ground-truth annotation flaws; for instance, 57% of examined entries within 70
the Virology subset contained labeling inconsistencies [ 1]. These discoveries have trig- 71
gered widespread skepticism across the community regarding the credibility of prevailing 72
evaluation ecosystems, to the extent that several scholars proclaimed the obsolescence of 73
the MMLU benchmark [ 6]. Banerjee et al. systematically diagnosed this methodological 74
predicament, demonstrating that static benchmark design philosophies, human annotation 75
protocols, and LLM-as-judge evaluation architectures all carry inherent drawbacks that 76
collectively compromise the validity of modern performance quantification [ 2]. In their 77
exhaustive survey covering LLM agent evaluation, Yehudai et al. documented an ongoing 78
community-wide transition toward more realistic, challenging, and dynamically updatable 79
benchmark suites that evolve synchronously with advancing model capacities [3].80

2.1. Static Benchmarks and Their Limitations 129
The assessment of large language models has long been anchored to static benchmarks, 130
which quantify the intrinsic competence of models via zero-shot or few-shot testing on 131
fixed test corpora. In their seminal work on GPT-3, Brown et al. validated the strong task 132
adaptability of language models under few-shot conditions, thereby consolidating zero-shot 133
and few-shot evaluation as mainstream experimental paradigms [ 34]. In the subsequent 134
years, static test suites including MMLU [ 7], GSM8K [ 8], and BIG-Bench-Hard [ 10] have 135
evolved into standard instrumentation for gauging the generalizable capabilities of LLMs. 136
Nevertheless, the credibility of such static benchmarks has been subject to mount- 137
ing skepticism within the research community [ 1,2,35]. Recent empirical investigations 138
reveal that state-of-the-art LLMs attain over 90% prediction accuracy on MMLU, indi- 139
cating pronounced performance saturation [ 1,36]. Gema et al. [ 1,36] further carried out 140
a rigorous error auditing on MMLU and detected widespread ground-truth annotation 141
defects; concretely, 57% of sampled items in the Virology subset were plagued by labeling 142
inconsistencies. Such empirical outcomes have prompted pervasive doubts regarding the 143
robustness of prevailing evaluation pipelines [ 2,6,35]. To mitigate the saturation dilemma, 144
scholars have put forward more difficult benchmark derivatives exemplified by MMLU- 145
https://doi.org/10.3390/1010000

Pro[ 11] and MMLU-ProX[ 12]. This variant enlarges candidate answer choices from 4 to 146
10, eliminates trivial test items, and prioritizes multi-step reasoning tasks to alleviate the 147
shortcut memorization bias prevalent in LLMs. 148
Apart from performance saturation, static benchmarks are confronted with more crit- 149
ical methodological drawbacks. Banerjee et al. [ 2] delivered a comprehensive diagnosis 150
of this predicament, demonstrating that inherent flaws embedded in static benchmark 151
design, human annotation protocols, and LLM-as-judge evaluation architectures collec- 152
tively degrade the validity of modern performance quantification. Yin et al. [ 6] insightfully 153
noted that assessments built upon fixed question banks or constrained paraphrase sets lack 154
both reliability and exhaustiveness, largely owing to the extreme prompt susceptibility 155
exhibited by large language models. To tackle this pitfall, the authors proposed the notion 156
of the knowledge boundary, which distinguishes between prompt-agnostic knowledge and 157
prompt-dependent susceptible knowledge encoded inside model parameters [6].158
Taken together, these drawbacks converge toward a more essential flaw: static bench- 159
marks presuppose invariant model internal states throughout the evaluation process, and 160
thus fail to characterize the dynamic performance drift induced by continuous real-world 161
interactive deployment [3]. 162
2.2. Dynamic and Streaming Evaluation 163
As large language models are increasingly integrated into agent-based frameworks, 164
growing research attention has been directed toward their post-deployment progressive 165
adaptation capabilities. Madaan et al. [ 24] put forward MemPrompt, a pioneering study 166
verifying that GPT-3 achieves incremental performance gains via persistent storage of 167
user feedback. Shinn et al. [ 25] validated through Reflexion that LLM agents are capable 168
of iterative performance enhancement on fixed datasets by virtue of self-reflection and 169
repeated trial-and-error attempts. Zhao et al. [ 26] further demonstrated via ExpEL that 170
LLM agents are able to transfer cross-task experiential knowledge, eliminating the need 171
for redundant repetitive trials on target downstream tasks. Collectively, these studies 172
underline a pivotal research tendency: LLMs possess the capacity not merely for one-shot 173
knowledge acquisition, but also for sustained lifelong evolution.174
StreamBench [ 4] bridges a prominent research gap within this evaluation dimension. 175
Wu et al. [ 4] formally constructed a specialized benchmark tailored to quantify the continu- 176
ous progressive learning capacity of LLM agents within sequential input-feedback streams. 177
StreamBench covers a suite of practical real-world scenarios, ranging from Text-to-SQL 178
conversion, Python programming and tool invocation to medical diagnosis and open- 179
domain question answering, while establishing multiple baseline algorithms including 180
GrowPrompt, MemPrompt, ASK-StreamDiag and MAM-StreamICL. Their empirical evi- 181
dence corroborates that iterative user feedback yields substantial accuracy uplifts for LLMs 182
on target tasks, thereby delivering solid empirical evidence to underpin the construction of 183
dynamic evaluation paradigms. 184
Nevertheless, StreamBench, akin to other dynamic evaluation benchmarks, is con- 185
strained by low-resolution feedback pipelines that only yield simplistic binary pass/fail 186
annotations as final evaluation outputs. While such dichotomous feedback enables longi- 187
tudinal tracking of performance improvements, it fails to unpack the internal mechanics 188
behind performance increments or clarify why certain optimization strategies function 189
effectively at the atomic subtask granularity [3]. 190
2.3. Fine-Grained Process-Aware Evaluation 191
Prior literature discussed so far predominantly addresses the macroscopic research 192
question of whether performance gains can be achieved, yet overlooks process-aware 193

inquiries regarding how such improvements are materialized and why particular optimiza- 194
tion strategies take effect. Recent scholarship has shifted toward finer-grained evaluation 195
paradigms, with the objective of dissecting the underlying inferential workflows inside 196
large language models. 197
Within the scope of logical reasoning assessment, Zhou et al. [ 27] devised the FineL- 198
ogic framework to quantify LLMs’ logical reasoning proficiency along three orthogonal 199
metrics: overall predictive accuracy, rationality at each individual reasoning step, and 200
representational alignment. Their core assertion—that conventional benchmarks hinging 201
merely on final answer accuracy fail to quantify the quality of intermediate reasoning 202
chains—strongly resonates with the core motivation of our present work.203
Process Reward Models (PRMs) constitute another relevant line of advancement in 204
process-oriented supervision techniques [ 28]. Distinct from Outcome Reward Models that 205
exclusively score final outputs, PRMs deliver stepwise evaluation and impose guidance 206
on iterative reasoning procedures. She et al. [ 29] put forward R-PRM (Reasoning-Driven 207
Process Reward Modeling), which activates the intrinsic reasoning capacity of LLMs to 208
strengthen process-level diagnostic assessment. Zheng et al. [ 28] presented a holistic survey 209
summarizing PRM research progress, and highlighted that fine-grained process supervision 210
stands as a critical technical pathway to boost the reasoning robustness of LLMs.211
Parallel progress on fine-grained evaluation has also proliferated across alternative 212
task domains. For the medical diagnosis scenario, scholars introduced HDCEval, a metric 213
system conducting multi-dimensional assessment covering patient question pertinence, cor- 214
rectness of medical domain knowledge, and linguistic expression quality. This benchmark 215
is constructed upon fine-grained evaluation protocols jointly formulated with practicing 216
clinicians. Hong et al. [ 32] presented UFEval, the first generalized unified fine-grained 217
evaluator supporting cross-task and cross-aspect generalization over four downstream 218
tasks. Built upon the FRABench dataset containing 60.4k pairwise annotated samples 219
that cover 112 heterogeneous evaluation dimensions, this tool achieves broad applicability 220
across diverse evaluation facets. 221
2.4. Knowledge Boundary and LLM-as-a-Judge 222
When exploring the boundary of model capability limits, the knowledge boundary 223
framework serves as a vital theoretical analytical perspective. Yin et al. [ 6] put forward this 224
formulation to resolve the inherent vulnerability of large language models toward prompt 225
lexical variations: identical underlying knowledge manifests drastically divergent outputs 226
under distinct prompt templates. The authors taxonomize model internal knowledge 227
into prompt-agnostic knowledge and prompt-sensitive knowledge. This categorization 228
abandons the oversimplified binary dichotomy of "knowledge presence versus absence", 229
and instead shifts the research focus to the expressive form of encoded knowledge as well 230
as the conditional prerequisites for its effective activation.231
This theoretical framework delivers a powerful diagnostic tool for root-cause analysis 232
of model failure cases. For a task failure event, the underlying driver rarely stems from gen- 233
uine knowledge deficiency; more frequently, it arises from the failure of internal knowledge 234
to be successfully triggered by the given prompt formulation. The dichotomy between 235
Model-Specific Unknowns (MSU) and Prompt-Sensitive Known (PSK) can be seamlessly 236
embedded into fine-grained evaluation pipelines. Within our proposed framework, per- 237
formance fluctuations of identical failed test samples under varied prompt settings are 238
treated as diagnostic indicators to distinguish the two failure modes. Specifically, MSU 239
corresponds to persistent task failure across all prompt rewrites, which strongly suggests 240
critical knowledge gaps[35]. By contrast, PSK refers to volatile performance outcomes un-241

In parallel, the LLM-as-a-judge paradigm has evolved into a scalable substitute for 244
costly human annotation. Nevertheless, cumulative existing literature has exposed sub- 245
stantial inherent drawbacks of this evaluation paradigm. Empirical evidence demonstrates 246
that if the referee model exhibits no superiority in accuracy relative to the evaluated tar- 247
get model, debiasing algorithms are unable to reduce over half of the required manually 248
annotated ground-truth labels. This observation reveals severe bottlenecks restricting the 249
applicability of LLM-as-judge at the cutting edge of evaluation research. To circumvent 250
such pitfalls in our fine-grained streaming evaluation framework, we adopt a referee 251
LLM with validated stronger overall performance than all tested target models, thereby 252
substantially alleviating the aforementioned reliability risks[2,35].253
2.5. Summary and Positioning 254
In summary, existing evaluation approaches can be categorized into three paradigms. 255
Static benchmarks (Section 2.1) provide coarse-grained final-answer labels but offer no 256
support for diagnosing internal failures and cannot capture continuous improvement. 257
Dynamic streaming benchmarks (Section 2.2), exemplified by StreamBench, can track im- 258
provement over time but still output only binary feedback without explaining why models 259
fail. Fine-grained process-aware evaluation (Sections 2.3–2.4) has emerged across multiple 260
domains—including logical reasoning (FineLogic), step-level supervision (PRMs), medical 261
evaluation (HDCEval), and unified fine-grained evaluators (UFEval)—demonstrating the 262
value of process-level assessment. 263
Our framework unifies and extends these strands of work by integrating atomic 264
sub-task decomposition, multi-agent LLM-based diagnostic evaluation, and knowledge 265
boundary classification (MSU vs. PSK) within a streaming evaluation environment. This 266
design moves beyond “outcome-based” evaluation toward “process-based process-aware 267
analysis,” enabling precise failure localization, adaptive model routing, and visualizable 268
capability profiles. Leveraging the StreamBench platform [ 4], we systematically validate 269
the proposed framework across five representative tasks.270
2.6. Reliability issues of LLM - as - judge 271
Despite its efficacy, the deployment of LLMs as evaluators introduces inherent reli- 272
ability concerns [? ?]. Studies have demonstrated that judge LLMs are susceptible to 273
various biases, including positional bias, verbosity bias, and self-enhancement, which can 274
compromise the fidelity of the evaluation [?]. Our framework mitigates these risks by 275
employing a multi-pronged strategy: (1) utilizing a high-capability judge (GPT-4) with a 276
low-temperature setting to ensure deterministic outputs; (2) requiring the judge to provide 277
structured evidence and reasoning for its decisions; and (3) when applicable, aggregating 278
judgments from multiple models or using iterative cross-verification to enhance the ro- 279
bustness of the final diagnosis. This rigorous design ensures that the diagnostic feedback 280
is not only fine-grained but also sufficiently reliable to inform downstream deployment 281
decisions. 282

3.2. Knowledge Boundary Framework 310
3.2.1. Model-Specific Unknowns (MSU) 311
Following Yin et al. [ 6], we adopt the knowledge boundary framework. For any given 312
task (or sub-task), a model’s behavior can be classified into two types. The first type isMSU: 313
the model consistently fails on the task even when the prompt is varied (e.g., rephrasing, 314

5.5. System Implementation Details 636
The system is implemented in Python. The StreamBench evaluation protocol is re- 637
produced locally. For each dataset, the stream is processed sequentially: the target model 638
receives the current task xtalong with memory examples (if any), produces an answer, and 639
receives binary feedback. In our method, before the final answer is produced, Stages 1–3 are 640
executed: sub-task decomposition (using GPT-3.5), judge evaluation (GPT-4), and failure 641
classification. The memory is updated only with successful examples (overall correctness). 642
For MSU failures, the framework either retrieves a stored correct example or routes to 643
a different model based on pre-computed capability profiles. For PSK failures, a prompt 644
rephrasing is attempted. All experiments are run on a single node with API calls man- 645
aged via request throttling. Each dataset’s streaming order is randomly shuffled before 646
evaluation to avoid ordering bias. The hyperparameter sets are all as follows in Table 5 647
and Algorithm 1. The code for reproducing the experiments is available at the project 648
repository. 649

6.3. Limitations of This Work 1222
This research acknowledges three clear limitations that constrain its full generalizabil- 1223
ity, which we frame objectively without undermining core findings. First, all task instances 1224
and judge diagnostic logic operate exclusively on text-only inputs; the current pipeline 1225
cannot process multi-modal tasks with visual, audio, or spatial context. As shown in our 1226
spatial reasoning case study, text-based judge LLMs produce unreliable sub-task judgments 1227
for vision-dependent problems, breaking the MSU/PSK classification workflow. Second, 1228
our experimental scope is limited to four mainstream text LLMs (Qwen, Kimi-k2.6, Zhipu 1229
GLM-4, DouBao) and three fixed benchmark datasets; performance trends may shift drasti- 1230
cally for ultra-small edge LLMs or long-context document reasoning streams exceeding 1231
400 input tokens, where diagnostic accuracy drops below 70%. Third, the prompt pertur- 1232
bation module adds non-negligible inference latency and token consumption—while our 1233
cost-depth tradeoff analysis confirms controllable overhead for enterprise use, lightweight 1234
low-resource deployment scenarios would require further optimization to cut judge LLM 1235
invocation frequency. 1236
6.4. Future Research Directions 1237
Building on the identified limitations and open challenges in fine-grained streaming 1238
evaluation, we outline four concrete, actionable future research branches.1239
1. Multi-modal extension of the diagnostic framework: Integrate vision-language judge 1240
models (GPT-4o, multimodal GLM) to decompose and verify visual-spatial sub-tasks, 1241
expanding the framework from pure text to cross-modal streaming agent evaluation. 1242
2. Lightweight judge distillation: Distill the high-performance GPT-4 judge into small 1243
open-source evaluator LLMs, eliminating reliance on closed API judges and drastically 1244
reducing per-sample inference cost for edge streaming systems.1245
3. Dynamic adaptive sub-task granularity: Replace fixed domain decomposition tem- 1246

tasks based on input complexity, balancing diagnostic precision and computational 1248
efficiency for variable-length task streams. 1249
4. Knowledge boundary intervention research: Extend MSU/PSK classification to 1250
design targeted improvement pipelines—develop retrieval-augmented fine-tuning 1251
workflows for MSU permanent knowledge gaps, and automated prompt calibration 1252
pipelines for recurring PSK activation failures. 1253
